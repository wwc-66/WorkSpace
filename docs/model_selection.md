# 模型选型实验报告 (Model Selection Experiment v1)

## 实验目的
在保持 RAG 问答质量不变的前提下，对比 Qwen-Plus (云端免费)、DeepSeek-V4-Flash (云端付费)、Qwen3.8:27b (本地 Ollama) 的**端到端延迟**与**稳定性**，为后续开发工作选定默认推理模型。

## 实验环境
- 后端服务：本地 FastAPI + LangChain (RAG 检索)
- 硬件：本地 PC / 个人笔记本（Ollama 运行于 CPU/GPU）
- Case 集：15 个标准测试用例（含 RAG 检索与指令遵循）
- 测量指标：单次 `/ask` 请求的端到端延迟 (ms)，不含前端渲染

## 实验结果
| 模型 | 平均延迟 (ms) | 标准差 (ms) | 最高延迟 | 最低延迟 | 备注 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3.8:27b (本地) | 1002.0 | 586.6 | 2410 | 405 | 最快、最稳定 |
| Qwen-Plus (云端) | 1293.1 | 1342.3 | 4335 | 374 | 免费，但偶发长尾延迟 |
| DeepSeek-V4-Flash | 1361.5 | 792.4 | 3330 | 461 | 最贵，推理能力最强 |

## 选型结论
1. **默认开发模型**：Qwen3.8:27b（本地）。理由：延迟最低且稳定，零成本，适合高频迭代。
2. **兜底/批量测试**：Qwen-Plus（云端免费）。理由：当本地服务不可用时自动切换，节省 DeepSeek API 配额。
3. **高级推理任务**：DeepSeek-V4-Flash 按需调用。理由：仅在普通模型答错的边缘 Case 中使用，保证质量上限。

## V2 补充实验（复杂推理与多约束专项）

### 实验目的
V1 中三模型在 15 个基础 Case 上全部 100% 通过，无法区分能力差异。因此设计 V2 的 15 个高难度 Case（M01~M05），覆盖多约束、长上下文、证据推理、拒答、结构化转换五类能力。

### 实验结果
| 模型 | 通过率 | 主要失败模式 |
| :--- | :--- | :--- |
| Qwen3.8:27b (本地) | 93.33% | 单格字数超限（细节精度） |
| DeepSeek-V4-Flash | 86.67% | 结构化输出偏差、过度简答 |
| Qwen-Plus | 80% | 硬约束违反（字数/格式） |

### 关键发现
1. 本地 27B 模型在“指令遵循+格式约束”类任务上表现优于云端通用大模型。
2. 三种模型呈现明显不同的失败模式，说明“模型选型”必须按任务类型细分，而非单一总分排名。
3. 评估集本身也需要迭代（如 M01-3 的“开头逗号冲突”问题，已修正判定规则）。

### 选型结论
- **格式严格任务**：默认走本地 Qwen3.8:27b。
- **深度推理任务**：按需切 DeepSeek-V4-Flash。
- **批量宽松任务**：用 Qwen-Plus 免费额度。

## 未来改进方向
- 当前策略仅复核 false 的 Case，存在假阳性（true 但偶然）未被检出的风险。
- 改进方向：引入全量 Pass@K 稳定性评估，对所有 Case 做多次采样；
  或在 prompt 层引入同义改写变体，做交叉验证。
